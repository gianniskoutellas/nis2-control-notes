# 05 — Security in Acquisition, Development and Maintenance

## Obligation (plain language)

Entities must ensure security is considered when acquiring, developing and maintaining network and information systems, including vulnerability handling and disclosure.

## Control questions

- Are security requirements defined before acquiring or developing systems?
- Is there a change management process that includes security review?
- How are vulnerabilities in owned or used systems identified and treated?
- Is there a process for receiving and handling vulnerability reports?
- Are third-party components and libraries tracked for known issues?

## Example evidence

- Secure development / acquisition policy or checklist
- Change management records with security sign-off
- Vulnerability management procedure and recent scan / remediation reports
- Vulnerability disclosure / contact channel
- Software bill of materials (SBOM) or component inventory for critical systems (if used)

## Common gaps

- Security reviewed only after go-live
- No formal vulnerability handling process
- Shadow IT and unmanaged SaaS not in scope
